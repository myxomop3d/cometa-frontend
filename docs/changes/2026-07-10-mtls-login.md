# Авторизация: добавление входа по TLS-сертификату (mTLS)

Дата: 2026-07-10

## Что изменилось

### API (`src/api/auth.ts`)
- Добавлена функция `certLogin()` — POST к `/api/v1/auth/login` с пустым телом. Сертификат передаётся на уровне TLS-соединения, заголовок `x-forwarded-client-cert` формируется nginx-прокси.

### Auth context (`src/lib/auth/auth-context.tsx`)
- В интерфейс `AuthContextValue` добавлен `handleCertLogin: () => Promise<void>`.
- Добавлен метод `handleCertLogin` — вызывает `certLogin()`, сохраняет токен в `localStorage`, загружает профиль пользователя через `getMe()`, перенаправляет на `/automated-system`.

### Страница логина (`src/routes/login.tsx`)
- Под основной формой добавлена кнопка «Sign in by certificate» (`variant="outline"`, иконка `KeyRound`).
- Обработчик `onCertLogin` вызывает `handleCertLogin()`, при ошибке выводит сообщение о необходимости установки клиентского сертификата в браузере.
- Обе кнопки блокируются одновременно (`disabled={isSubmitting}`), чтобы избежать двойного вызова.

## Как работает

Пользователь выбирает один из двух способов входа:

1. **Legacy-вход** — email + пароль, форма отправляется как раньше.
2. **mTLS-вход** — кнопка «Sign in by certificate». Браузер автоматически отправляет клиентский сертификат на этапе TLS-рукопожатия. Nginx извлекает CN из сертификата, передаёт в `x-forwarded-client-cert`, сервер возвращает JWT.

### Сценарий ошибки

Если сертификат не установлен или не доверяется CA — сервер вернёт 401. Фронтенд покажет сообщение об ошибке в блоке `errors.root` под формой.

## Замечания / известные ограничения
- Требуется настройка nginx для mTLS (передача `x-forwarded-client-cert`).
- Нетsilent re-auth — при истечении токена (24 часа) или перезапуске сервера (регенерация HMAC-ключа) пользователь получает 401 и возвращается на `/login`.
- MSW-моки для `certLogin` не добавлены — для локальной разработки используется legacy-вход через `VITE_MOCK_API=true`.
